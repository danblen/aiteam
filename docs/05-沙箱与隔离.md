# 05 — 沙箱与隔离

## 多层隔离体系

项目设计了三个层次的隔离：

```
1. 进程级隔离 — 每个会话分配独立的 Linux UID
2. 文件系统隔离 — 每个 UID 的工作目录权限为 700
3. 版本控制隔离 — 每个会话在独立的 Git worktree 中工作
```

这些隔离只在 Docker 容器内生效（Linux）。在 macOS 开发环境中，所有函数是 no-op。

## UID 池管理

容器启动时，Dockerfile 预创建了 200 个 Linux 用户：

```dockerfile
RUN for i in $(seq 10000 10199); do
    useradd --no-log-init -M -K UID_MIN=$i -u $i sandbox-$i
done
```

运行时，`ensureIsolatedUser(sid)` 从池中分配一个 UID 给会话：

```
assignedUids: Set<number>         // 跟踪哪些 UID 已被占用
sessionToUid: Map<sid, number>    // 会话到 UID 的映射

分配逻辑: 找到第一个未占用的 UID → 标记为占用 → 返回
释放逻辑: removeIsolatedUser(sid) → userdel → 从集合中移除 → UID 可复用
```

为什么预创建而不动态创建？**权限问题**。`useradd` 需要 root 权限，但运行进程可能已经不是 root。提前创建好，运行时只做分配/释放。

## spawn 怎么切换用户

Node.js 的 `child_process.spawn({ uid, gid })` 在 root 权限下可以直接切换：

```javascript
function spawnAsUser(binPath, args, opts, uid) {
  const child = spawn(binPath, args, {
    ...opts,
    uid: uid,
    gid: uid,
    env: buildSandboxEnv(uid)
  });
  return child;
}
```

**环境变量清理**是关键。不能直接把当前进程的环境变量传给沙箱用户：

```javascript
function buildSandboxEnv(uid) {
  return {
    HOME: `/tmp/sandbox-${uid}`,          // 独立家目录
    PATH: '/usr/local/bin:/usr/bin:/bin',  // 最小 PATH
    npm_config_cache: `/tmp/.cache-${uid}`, // 独立 npm 缓存
    
    // 只透传 AI 提供程序密钥
    ANTHROPIC_API_KEY: process.env.ANTHROPIC_API_KEY,
    OPENAI_API_KEY: process.env.OPENAI_API_KEY,
    OPENAI_BASE_URL: process.env.OPENAI_BASE_URL,
    OPENAI_MODEL: process.env.OPENAI_MODEL,
  };
}
```

不传 `HOME` 给当前用户的家目录——不然不同会话的 CLI 工具可能读到对方的配置。

## 文件系统权限

分配 UID 后，工作目录做 `chown + chmod`：

```javascript
function secureWorkspace(dir, uid) {
  execSync(`chown -R ${uid}:${uid} "${dir}"`);
  execSync(`chmod 0700 "${dir}"`);
}
```

`0700` 意味着只有该 UID 能读写这个目录。其他会话的 UID 无法访问——即使它们知道文件路径。

## cgroup 资源限制

`setCgroupLimits(uid, { memory: '512m', cpu: '0.5' })` 通过 Linux cgroup v2 限制每个沙箱用户的资源使用：

```
写入 /sys/fs/cgroup/sandbox-{uid}/memory.max = 512m
写入 /sys/fs/cgroup/sandbox-{uid}/cpu.max = 50000 100000
                                          (= 50% of one CPU)
```

这防止某个会话的 CLI 进程耗尽容器资源影响其他会话。

## Git Worktree 会话隔离

这是版本控制层面的隔离。核心思路：**每个会话在独立的 Git 分支上工作，互不影响**。

```
主干分支(main): 项目的稳定版本

会话 A 创建 →  git worktree add .aiteam-worktrees/sessA/ session-sessA
            →  在独立目录中工作，分支 session-sessA

会话 B 创建 →  git worktree add .aiteam-worktrees/sessB/ session-sessB
            →  在独立目录中工作，分支 session-sessB
```

工作树目录位于项目 `.git` 目录旁边，通过 `.gitignore`/`.git/info/exclude` 排除，不会影响主干。

### 生命周期

```
创建项目 → git init + 空初始提交
绑定会话 → git worktree add (创建新分支)
开发     → AI 在工作树中修改文件
合并     → git add -A → git commit → git merge --no-ff → 主干
清理     → git worktree remove → 删除分支引用
```

### ensureGitRepo 的鲁棒性

`ensureGitRepo(dir)` 处理了多种边界情况：

```javascript
// 1. 检查是否已经在 git 仓库中
git rev-parse --is-inside-work-tree → 是 → 直接返回

// 2. 不是 → git init
// 3. 把 .aiteam-worktrees/ 加到 .git/info/exclude（不污染 .gitignore）
// 4. 如果没有提交 → git commit --allow-empty -m "init"
//    (worktree 需要至少一个提交作为基础)
```

## OpenCode 配置的沙箱化

OpenCode 需要从 `~/.config/opencode/opencode.jsonc` 读取 API 密钥。在沙箱环境中，每个 UID 有独立的家目录，所以需要为每个 UID 生成配置文件：

```javascript
function ensureOpenCodeConfig(uid) {
  const configDir = `/tmp/sandbox-${uid}/.config/opencode/`;
  mkdirSync(configDir, { recursive: true });
  
  // 从模板生成（模板缓存在 /tmp/aiteam-opencode.jsonc）
  // 替换 API key、base URL、model
  writeFileSync(`${configDir}/opencode.jsonc`, renderedConfig);
}
```

模板缓存在 `/tmp/` 下，新会话直接从模板渲染，不需要每次都重新构建。

## 工作区访问控制

除了 Linux 级别的权限，Express 层也有访问控制：

```javascript
function canAccessWorkPath(req, targetPath) {
  // 管理员 → 任何路径
  if (isAdmin(req)) return true;
  
  // 普通用户 → 只能访问自己工作区内的路径
  const userRoot = `/workspaces/${req.user.email}/`;
  return targetPath.startsWith(userRoot);
}
```

这是为了**云端多租户场景**——多个用户共享同一个 Express 后端，但各自的工作目录不同。
